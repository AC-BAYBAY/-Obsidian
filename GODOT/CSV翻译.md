# CSV 翻译

要将游戏翻译成多种语言，Godot 提供了一种非常便捷的内置方案：**CSV 翻译导入器**。它允许你直接用电子表格（如 Excel、Google Sheets）管理所有文本，然后一键导入引擎。

下面是一份使用指南，整理了从文件准备到导入设置的完整流程。

> [!info] 关联笔记
> 关于 CSV 在 Godot 中的更广泛用途（物品属性数据管理 + 多语言支持完整方案），请参阅 [[GODOT/CSV|CSV 数据驱动]] 笔记。

## 🌍 游戏国际化的两种思路

在开始制作多语言游戏前，了解两种主流的文本管理思路很有帮助：

- **以源语言为键（如英语）**：适合先推出单一语言版本，后期再追加翻译的游戏。开发初期更直接，但在同时处理多种语言时容易造成混乱。
- **使用唯一标识符（ID）**：为每段文本分配一个独立的 ID（如 `GREET`、`ASK`）。这是游戏开发中普遍推荐的做法，因为它允许在翻译过程中随时修改源文本，管理更灵活。

## 📝 准备翻译表（CSV 文件）

为了配合 Godot 的导入器，CSV 文件需要遵循特定的格式规范。

### 核心规则

- **文件编码**：必须保存为 **UTF-8 编码**，且不能包含**字节顺序标记（BOM）**。
- **列布局**：第一列是**键（Keys）**，后续的每一列代表一种**语言**。
- **表头**：
  - 左上角第一个单元格（A1）内容随意，导入时会被忽略。
  - 第一行的其他单元格必须是代表语言的**语言环境标签（Locale）**，例如 `en`（英语）、`zh`（中文）等。这些标签需要是 Godot 引擎支持的合法标识符。
- **行内容**：
  - 第一列（Keys）必须是**唯一**的字符串，大小写敏感（`KEY1` 和 `Key1` 视为不同）。
  - 每一行对应一个键，并在不同语言列下填入相应的翻译文本。

### ⚠️ 特殊注意事项

- **避免使用 Excel**：默认情况下，Microsoft Excel 会将 CSV 文件保存为 ANSI 编码，而非 UTF-8。建议使用 **LibreOffice** 或 **Google Sheets** 等工具来编辑和导出。
- **处理特殊字符**：如果文本中包含逗号、换行符或双引号，需要用双引号将其包裹起来；文本内的双引号本身则要用两个双引号（`""`）来转义。

### 示例表格

一个完整的表格看起来是这样的：

| keys | en | zh |
| :--- | :--- | :--- |
| GREET | Hello, friend! | 你好，朋友！ |
| ASK | How are you? | 你好吗？ |
| BYE | Goodbye | 再见 |
| QUOTE | "Hello" said the man. | "你好"，男人说。 |

以逗号分隔的纯文本形式则为：

```csv
keys,en,zh
GREET,"Hello, friend!","你好，朋友！"
ASK,How are you?,"你好吗？"
BYE,Goodbye,再见
QUOTE,"""Hello"" said the man.","""你好""，男人说。"
```

## ⚙️ 在 Godot 中导入与设置

文件准备好后，可以按以下步骤导入到 Godot 项目中：

1. **导入文件**：将 `.csv` 文件直接拖拽或复制到 Godot 项目的文件系统（FileSystem）面板中。Godot 会默认将其识别为翻译文件并自动导入。
2. **配置导入选项**：在文件系统中选中该 `.csv` 文件，然后点击编辑器上方的 **"导入"（Import）** 标签页。你可以看到两个主要选项：
   - **压缩（Compress）**：设置导入的翻译资源是否进行压缩。
   - **定界符（Delimiter）**：设置 CSV 文件解析时使用的分隔符，默认为逗号，你也可以根据需要更改。
3. **重新导入**：每次修改导入选项后，都需要点击 **"重新导入"（Reimport）** 按钮，确保更改生效。
4. **运行时加载**：导入成功后，翻译会自动添加到游戏的翻译列表，并可在运行时被加载和使用。

### 在代码中使用翻译

```gdscript
# 获取当前语言的翻译文本
tr("GREET")   # 根据当前语言返回 "Hello, friend!" 或 "你好，朋友！"

# 切换游戏语言
TranslationServer.set_locale("en")   # 切换到英文
TranslationServer.set_locale("zh")   # 切换到中文
```

### 在场景中使用

选择任意包含文本的控件（如 Label、Button），将文本内容直接设置为键名（如 `GREET`），Godot 会在运行时自动翻译。

## 🔧 更多高级特性

除了基础文本替换，Godot 的 CSV 翻译导入器还支持一些更复杂的本地化场景：

### 忽略注释列

如果某列的标题以下划线 `_` 开头（如 `_Comment`），该列在导入时会被忽略。这很适合在表格中留下备注信息。

### 使用"上下文（Context）"

- **作用**：用于区分游戏中同一个键在不同情境下的翻译。例如，英文单词 "Letter" 既可以指"字母"，也可以指"信件"。
- **格式**：需要在表格中添加一个标题为 `?context` 的特殊列。

```csv
keys,?context,en,zh
Letter,Alphabet,Letter,字母
Letter,Message,Letter,信件
```

> 使用上下文后，在 GDScript 中调用 `tr("Letter", "Alphabet")` 即可获取具体语境下的翻译。

### 处理"复数形式（Plural）"

- **作用**：许多语言对单复数的处理比英语更复杂。此特性用于处理 `tr_n()` 函数调用，确保复数形式在不同语言中正确显示。
- **格式**：需要添加一个标题为 `?plural` 的特殊列，来指定源字符串的复数形式。
- **扩展复数行**：在定义复数的主行之后，可以追加额外的行来提供更多复数形式的翻译。这些行的第一列和所有特殊列（如 `?context`）都必须留空。

```csv
keys,?plural,en,zh
?pluralrule,,nplurals=2; plural=(n>=2);,
There is %d apple,There are %d apples,有 %d 个苹果
,,,有 %d 个苹果
```

## 💎 总结

总的来说，使用 Godot 内置的 CSV 翻译导入器，能让游戏本地化工作流程清晰、高效。核心要点：

1. **文件格式**：UTF-8 编码，第一列是键，后续列为各语言 locale
2. **导入方式**：丢入项目即可自动识别，在 Import 面板配置后 Reimport
3. **使用方式**：`tr(KEY_NAME)` 获取翻译，`TranslationServer.set_locale()` 切换语言
4. **高级功能**：支持上下文（`?context`）、复数形式（`?plural`）、注释列（`_` 开头）
