# Godot 数据保存方案汇总

Godot 提供多种数据保存方案，各有优劣，适用于不同场景。以下对 7 种常用方案进行详细盘点。

---

# 1️⃣ ConfigFile（INI 格式）

## 核心概念

使用 Godot 内置的 `ConfigFile` 类将数据以 **INI 格式**保存为本地文件。INI 格式由**小节（Section）**和**键值对（Key-Value）**共同组成，一个小节可以存储多个键值对。

适合保存**简单的配置数据**、游戏设置等，不适合保存地图等复杂内容。

## 关键节点/类及作用

| 节点/类 | 作用 | 关键用法 |
|---------|------|---------|
| **ConfigFile** | 创建/读取配置文件对象 | `ConfigFile.new()` |
| `LineEdit` | 玩家文本输入（如名字） | `.text` 属性获取字符串 |
| `ColorPickerButton` | 玩家颜色选择器 | `.color` 属性获取颜色 |
| `@export var` | 绑定 UI 节点到脚本 | `@export var player_name: LineEdit` |
| `pressed` 信号 | 按钮点击触发保存/加载 | 连接到 `save()` / `load()` 函数 |
| `user://` | 跨平台安全存档路径 | Windows → `%appdata%/Godot/app_user_data/<项目名>/` |

## 使用方法

### 保存数据

```gdscript
var config = ConfigFile.new()

# set_value(section, key, value)
config.set_value("Player1", "player_name", "Alice")
config.set_value("Player1", "best_score", 100)
config.set_value("Player2", "player_name", "Bob")
config.set_value("Player2", "best_score", 200)

config.save("user://settings.cfg")
```

### 读取数据

```gdscript
var config = ConfigFile.new()
var result = config.load("user://settings.cfg")

if result == OK:
    var name = config.get_value("Player1", "player_name")
    var score = config.get_value("Player1", "best_score")
```

### 加密存档

```gdscript
var key: String = "my_secret_key"

func save_encrypted():
    var config = ConfigFile.new()
    config.set_value("settings", "name", player_name.text)
    config.set_value("settings", "color", player_color.color)
    config.save_encrypted_pass("user://settings.cfg", key)

func load_encrypted():
    var config = ConfigFile.new()
    var result = config.load_encrypted_pass("user://settings.cfg", key)
    if result == OK:
        player_name.text = config.get_value("settings", "name")
        player_color.color = config.get_value("settings", "color")
```

## 文件格式示例

```ini
[Player1]
player_name="Alice"
best_score=100

[Player2]
player_name="Bob"
best_score=200
```

- 使用中括号 `[]` 包裹不同的小节
- 小节后跟着对应的键值对
- 结构扁平化，解析速度快
- 不支持小节嵌套

## 支持的数据类型

| 类型 | 示例 |
|------|------|
| `String` | 字符串 |
| `int` | 整数 |
| `float` | 浮点数 |
| `Color` | 颜色 |
| `Vector2` / `Vector3` | 向量 |
| `Array` | 数组 |
| `Dictionary` | 字典 |
| Variant 类型 | Godot 自带类型均有原生支持 |
| Resource | 支持序列化为纯文本格式保存 |

## 文件保存位置

| 系统 | 路径 |
|------|------|
| **Windows** | `%appdata%/Godot/app_user_data/<项目名>/` |
| **macOS** | `~/Library/Application Support/Godot/app_user_data/<项目名>/` |
| **Linux** | `~/.local/share/godot/app_user_data/<项目名>/` |

> Windows 下按 `Win + R` → 输入 `%appdata%` → 打开 `Godot/app_user_data/<项目名>` 即可找到存档文件。

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 开箱即用、内置加密支持、解析速度快、支持 Variant 类型 |
| 缺点 | 不支持小节嵌套、明文保存（未加密时）、不适合复杂数据 |
| 适合场景 | 简单配置、玩家设置、小体量游戏 |
| Godot 支持度 | ⭐⭐⭐⭐⭐ |
| 推荐度 | ⭐⭐⭐⭐⭐ |

# 2️⃣ JSON

## 核心概念

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式。Godot 中 JSON 的序列化基于**字典（Dictionary）**，通过 `JSON` 类实现序列化和反序列化。

## 使用方法

### 保存数据

```gdscript
var data = {
    "player_name": "Alice",
    "best_score": 100,
    "level": 5,
    "inventory": ["sword", "potion", "shield"]
}

var json_string = JSON.stringify(data)

var file = FileAccess.open("user://save.json", FileAccess.WRITE)
file.store_string(json_string)
```

> `JSON.stringify()` 默认输出压缩格式（无缩进），如需可读格式化可以传入第二个参数，如 `JSON.stringify(data, "\t")`。

### 读取数据

```gdscript
var file = FileAccess.open("user://save.json", FileAccess.READ)
var json_string = file.get_as_text()

var json = JSON.new()
var result = json.parse(json_string)

if result == OK:
    var data = json.data  # 解析为 Dictionary
    print(data["player_name"])
```

## 文件格式示例

```json
{"player_name":"Alice","best_score":100,"level":5,"inventory":["sword","potion","shield"]}
```

- 以对象 `{}` 为基础
- 支持字符串、数字、数组、布尔值、null 等类型
- 非常通用的保存格式

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 通用性强（跨语言、跨平台）、可读性好、结构灵活（支持嵌套） |
| 缺点 | 体积相对二进制大、无内置加密 |
| 适合场景 | 大部分游戏存档场景、网络数据传输 |
| Godot 支持度 | ⭐⭐⭐⭐⭐ |
| 推荐度 | ⭐⭐⭐⭐⭐ |

# 3️⃣ CSV

## 核心概念

CSV（Comma-Separated Values）以**逗号分隔值**的格式保存二维表格数据。在 Godot 中通常用于**国际化文件**，在常规游戏开发中用于保存二维表格数据。

## 使用方法

### 保存数据

```gdscript
var file = FileAccess.open("user://data.csv", FileAccess.WRITE)

# 第一行：表头
file.store_csv_line(["item_id", "item_name", "price", "type"])

# 后续行：数据
file.store_csv_line(["1", "铁剑", "100", "武器"])
file.store_csv_line(["2", "药水", "50", "消耗品"])
file.store_csv_line(["3", "盾牌", "200", "防具"])
```

### 读取数据

```gdscript
var file = FileAccess.open("user://data.csv", FileAccess.READ)

while file.get_position() < file.get_length():
    var line = file.get_csv_line()
    print(line)  # 返回字符串数组
```

## 文件格式示例

```
item_id,item_name,price,type
1,铁剑,100,武器
2,药水,50,消耗品
3,盾牌,200,防具
```

> 注意：`store_csv_line()` 和 `get_csv_line()` 方法仅支持以**字符串**方式存取数据，有局限性。

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 简单直观、可用 Excel 等工具编辑、适合少量二维表格数据 |
| 缺点 | 仅支持字符串存取、不支持复杂嵌套结构、操作麻烦 |
| 适合场景 | 国际化文件（翻译表）、游戏配置表（随游戏打包）、少量物品道具配置 |
| Godot 支持度 | ⭐⭐⭐ |
| 推荐度 | ⭐⭐⭐ |

> 在 Godot 中 `Resource` 是 CSV 的上位替代方案，推荐优先使用 Resource 而非 CSV。

# 4️⃣ XML

## 核心概念

XML（Extensible Markup Language）是一种**可扩展标记语言**，基于标签结构，专门设计用于传输数据。格式类似 HTML。

> **注意**：Godot 目前**仅支持解析 XML**，不支持序列化（生成）XML。

## 使用方法

### 解析 XML 文件

```gdscript
var xml_parser = XMLParser.new()
xml_parser.open("user://data.xml")

while xml_parser.read() == OK:
    var node_type = xml_parser.get_node_type()
    
    if node_type == XMLParser.NODE_ELEMENT:
        var node_name = xml_parser.get_node_name()
        var attr_value = xml_parser.get_named_attribute_value_safe("attribute_name")
        print("节点: ", node_name, " 属性: ", attr_value)
```

## 文件格式示例

```xml
<root>
    <player name="Alice" score="100" />
    <player name="Bob" score="200" />
    <item id="1" name="铁剑" type="武器" />
</root>
```

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 结构清晰、支持复杂嵌套、跨语言标准 |
| 缺点 | 文件体积大、冗余多、Godot 不支持序列化（只能解析）、使用麻烦 |
| 适合场景 | 勉强用于内部配置文件 |
| Godot 支持度 | ⭐⭐ |
| 推荐度 | ⭐ |

> XML 格式文件体积较大，冗余较多，不适合用户存档，Godot 支持也较差。

# 5️⃣ 二进制（Binary / FileAccess）

## 核心概念

通过 `FileAccess` 的原生方法，将数据以**二进制形式**保存在文件中。Godot 支持两种二进制数据的存取方式：

1. **原生二进制**：使用 `store_8/16/32/64` 或 `store_buffer` 保存字节或缓冲区
2. **Variant 序列化**：使用 `get_var()` / `store_var()` 读写 Godot 的原生 Variant 类型

## 使用方法

### 保存数据（按顺序写入）

```gdscript
var file = FileAccess.open("user://save.bin", FileAccess.WRITE)

# 必须按照固定顺序写入
file.store_32(player_id)       # 先保存玩家 ID
file.store_string(player_name) # 再保存玩家名称
file.store_32(best_score)      # 最后保存分数
```

### 读取数据（按顺序读取）

```gdscript
var file = FileAccess.open("user://save.bin", FileAccess.READ)

# 必须按照写入的相同顺序读取
var player_id = file.get_32()       # 先读玩家 ID
var player_name = file.get_string() # 再读玩家名称
var best_score = file.get_32()      # 最后读分数
```

### 使用 Variant 序列化

```gdscript
# 保存
var data = {
    "player_id": 1,
    "player_name": "Alice",
    "best_score": 100
}
var file = FileAccess.open("user://save.bin", FileAccess.WRITE)
file.store_var(data)

# 读取
file = FileAccess.open("user://save.bin", FileAccess.READ)
var loaded_data = file.get_var()
```

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 数据密集程度高、文件体积小、读取速度快 |
| 缺点 | 可维护性差、数据必须按照保存的顺序和格式读取、版本迭代容易导致旧存档损坏 |
| 适合场景 | 缓存数据、需要高性能读写的内部数据 |
| Godot 支持度 | ⭐⭐⭐⭐ |
| 推荐度 | ⭐⭐ |

### ⚠️ 版本兼容性问题

如果游戏版本迭代时在中间增添了一些数据，读取旧存档会导致数据损坏，必须手动实现**向下和向上兼容**。

```gdscript
# 旧版本：保存顺序为 [ID, 名称, 分数]
# 新版本：保存顺序为 [ID, 名称, 等级, 分数] ← 中间插入了"等级"

# 读取旧存档时会出错，需要增加版本判断逻辑
```

> 由于兼容性问题，二进制格式不建议用于玩家存档，更适合内部缓存等场景。

# 6️⃣ Resource（资源文件）

## 核心概念

基于 Godot 内置的 `Resource` 类实现数据序列化，是最快捷、最方便的资源存取方法。需要**自定义继承 Resource 的子类**作为数据载体。

Godot 支持两种保存格式：
- **`.res`**：二进制表示，节省空间，解析速度快
- **`.tres`**：明文表示（文本格式），人类可读，便于调试

## 关键节点/类及作用

| 节点/类                  | 作用              | 关键用法                                             |
| --------------------- | --------------- | ------------------------------------------------ |
| **自定义 Resource 类**    | 存档的数据结构载体       | `extends Resource` + `class_name SceneData`      |
| `@export var`         | 声明可序列化保存的变量     | `@export var player_position: Vector2`           |
| `@export_storage var` | 另一种导出方式         | 只用于序列化，不在编辑器显示                                   |
| `ResourceSaver`       | 将 Resource 写入硬盘 | `ResourceSaver.save(data, "user://...")`         |
| `ResourceLoader`      | 从硬盘读取存档         | `ResourceLoader.load("user://...") as SceneData` |
| `PackedScene`         | 将整个节点打包保存       | `.pack(node)` 打包 → `.instantiate()` 还原           |
| **Group（分组）**         | 给节点打标签，批量获取     | `get_tree().get_nodes_in_group("box")`           |

## 使用方法

### 1. 创建自定义存档数据类

```gdscript
# res://data/player_data.gd
extends Resource
class_name PlayerData

@export var player_id: int
@export var player_name: String
@export var best_score: int
```

### 2. 保存数据

```gdscript
var data = PlayerData.new()
data.player_id = 1
data.player_name = "Alice"
data.best_score = 100

ResourceSaver.save(data, "user://player_data.res")
```

### 3. 读取数据

```gdscript
var data = ResourceLoader.load("user://player_data.res") as PlayerData
if data:
    print(data.player_name)
```

### 4. 保存场景节点（PackedScene）

```gdscript
# 保存
var box_packed = PackedScene.new()
box_packed.pack(box_node)
ResourceSaver.save(box_packed, "user://box.scn")

# 加载
var box_scene = ResourceLoader.load("user://box.scn") as PackedScene
var box_node = box_scene.instantiate()
add_child(box_node)
```

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 原生支持、一行代码存取、支持资源文件和场景序列化、编辑器集成好 |
| 缺点 | 依赖对应类型脚本路径（脚本路径改变/删除/重命名会导致旧资源失效） |
| 适合场景 | 游戏内部配置（道具、关卡、物品等）、PCK 打包作为模组或 DLC 发布 |
| Godot 支持度 | ⭐⭐⭐⭐⭐ |
| 推荐度 | ⭐⭐⭐ |

### ⚠️ 脚本路径依赖问题

```gdscript
# 假设存档数据依赖 res://data/player_data.gd
# 如果后续更新重命名或移动了 player_data.gd
# 旧版本存档将无法读取！
# 错误信息：找不到对应类型的脚本
```

> **如果不考虑游戏更新**，可以无忧无虑地使用 Resource 保存存档。
>
> **如果游戏会持续更新**，Resource 更适合做**游戏内部配置**（道具、关卡等），可以随 PCK 打包作为模组或 DLC 发布，而非玩家存档。

# 7️⃣ SQLite（数据库）

## 核心概念

SQLite 是一种**无服务器**的嵌入式数据库，不像传统 MySQL、SQL Server 那样依赖网络服务。Godot 本身**不内置** SQLite 支持，需要通以下方式实现：

- **GDExtension / C++ 插件**：通过 GDNative / GDExtension 实现 SQLite 支持（如 [godot-sqlite](https://github.com/2shady4u/godot-sqlite) 插件）
- **C#**：利用 `System.Data.SQLite` 或 `Microsoft.Data.Sqlite` 实现

## 使用方法（以 GDExtension 插件为例）

### 打开数据库并执行 SQL

```gdscript
var sqlite = SQLite.new()
sqlite.open_db("user://game.db")

# 创建表
sqlite.query("
    CREATE TABLE IF NOT EXISTS players (
        id INTEGER PRIMARY KEY,
        name TEXT,
        score INTEGER
    )
")

# 插入数据
sqlite.query("INSERT INTO players VALUES (1, 'Alice', 100)")

# 参数化查询（防止 SQL 注入）
sqlite.query_with_bindings(
    "INSERT INTO players VALUES (?, ?, ?)",
    [2, "Bob", 200]
)

# 查询数据
sqlite.query("SELECT * FROM players")
var results = sqlite.query_result  # 查询结果保存在此字段

for row in results:
    print(row["name"], ": ", row["score"])

# 更新数据
sqlite.query_with_bindings(
    "UPDATE players SET score = ? WHERE id = ?",
    [150, 1]
)

# 删除数据
sqlite.query("DELETE FROM players WHERE id = 2")
```

## 优缺点

| 方面 | 说明 |
|------|------|
| 优点 | 支持海量数据、支持复杂查询（SQL）、支持事务、无服务器、跨平台 |
| 缺点 | Godot 不内置支持（需要插件/C#）、学习成本高、小型项目过重 |
| 适合场景 | 大世界游戏的 NPC 对话数据、海量单位的详细信息、中大型游戏 |
| Godot 支持度 | ⭐⭐ |
| 推荐度 | ⭐⭐ |

> 除特殊需求外，一般用不到 SQLite。中小型游戏使用 JSON 或 Resource 即可满足需求。

# 方案对比总表

| 方案 | 数据量 | 复杂度 | 可读性 | 跨版本兼容 | 加密支持 | Godot 支持度 | 推荐度 | 最佳场景 |
|------|--------|--------|--------|-----------|---------|-------------|--------|---------|
| **ConfigFile** | 小 | 低 | 高 | 好 | ✅ 内置 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 简单配置、游戏设置 |
| **JSON** | 中 | 低 | 高 | 好 | ❌ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 通用存档、网络传输 |
| **CSV** | 小（二维） | 低 | 高 | 好 | ❌ | ⭐⭐⭐ | ⭐⭐⭐ | 国际化表、物品配置表 |
| **XML** | 中 | 高 | 中 | 好 | ❌ | ⭐⭐ | ⭐ | 内部配置（不推荐） |
| **二进制** | 大 | 高 | 低 | **差** | 手动 | ⭐⭐⭐⭐ | ⭐⭐ | 缓存、高性能读写 |
| **Resource** | 中 | 中 | 中（.tres） | **差**（脚本路径依赖） | ❌ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 游戏内部配置、模组/DLC |
| **SQLite** | **海量** | 高 | 低 | 好 | ✅ | ⭐⭐ | ⭐⭐ | 大世界数据、中大型游戏 |

# 选择建议

| 你的需求 | 推荐方案 |
|---------|---------|
| 小体量游戏，保存玩家设置（音量、画质等） | **ConfigFile** |
| 通用存档，保存玩家进度、背包等 | **JSON** |
| 游戏内部配置（道具、关卡、物品表） | **Resource** |
| 需要存储和查询海量数据（大世界游戏） | **SQLite** |
| 国际化/多语言文本 | **CSV** |
| 模组 / DLC 资源包 | **Resource + PCK 打包** |
| 缓存数据，追求极致读写性能 | **二进制（Variant 序列化）** |
